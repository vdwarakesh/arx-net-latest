B-Tree

A B-Tree is a special type of self-balancing search tree designed to store multiple sorted keys inside every single node and branch out into dozens or even thousands of children, keeping the tree extremely wide and shallow for fast disk and storage access.

Imagine looking up a book in a massive library. If you had to walk up and down stairs to open a new cabinet for every single yes/no question (like a tall Binary Search Tree), your legs would be exhausted. Instead, each room has a long reference table listing 500 alphabetical dividers at once, so you only have to walk through two or three doors to reach any book among millions. A B-tree organizes data into wide "rooms" (disk blocks) in the exact same way.


Understanding the Basic Terminology

Minimum Degree (t) / Order (m): The rule governing how many keys and child pointers each node must hold (typically between t-1 and 2t-1 keys).

Multi-Way Branching (High Fanout): A node containing k sorted keys acts as a divider for k+1 child subtrees.

Node Splitting: When a node fills up beyond its maximum capacity during an insertion, it splits into two half-full nodes and pushes its middle key up into its parent node.

Perfect Height Balance: Unlike basic BSTs, a B-tree grows upward from the root rather than downward from the leaves, guaranteeing that every leaf node sits at the exact same depth.


How Does a B-Tree Work Conceptually?

Reading a single byte from a hard drive or SSD takes roughly the same time as reading an entire 4-kilobyte or 16-kilobyte block (page). A standard binary tree wastes this hardware trait by scattering tiny two-child nodes across memory, causing slow disk jumps at every level.

A B-tree sizes each node to match one physical storage page cleanly. With a branching factor of 1,000 keys per node, a B-tree only needs 3 levels to store a billion records-meaning any item can be located in at most 3 disk reads.


Where Are B-Trees Used in the Real World?

File Systems: Power directory and block metadata tables in Apple's HFS+/APFS, Linux ext4/Btrfs, and Windows NTFS.

Database Indexes: Store primary and secondary key indexes in relational and NoSQL storage engines.

Key-Value Storage Engines: Organize sorted on-disk tables that exceed available RAM.


Summary

A B-tree packs hundreds of sorted keys into each node to create a wide, ultra-shallow hierarchy, minimizing slow disk and memory jumps across massive datasets.
