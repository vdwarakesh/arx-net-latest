Link-Cut Tree

A Link-Cut Tree (invented by Daniel Sleator and Robert Tarjan) is a special type of dynamic tree data structure that maintains a forest of rooted trees and allows you to **cut branches apart**, **link separate trees together**, and **query or update any node-to-root path** in $\mathcal{O}(\log n)$ amortized time.

Imagine a railroad network shaped like a branching tree where some tracks have electric switches currently flipped "on" (forming active express routes) and side spurs have switches flipped "off." Whenever you want to run a train from any station all the way to the capital city, the Link-Cut Tree automatically flips the switches along your path into one continuous express line, letting you inspect or update the entire route in a single sweep.


Understanding the Basic Terminology

Preferred Child & Preferred Path: Each node remembers which of its children was accessed most recently. Chaining these "preferred" edges together breaks the entire tree into a set of disjoint vertical **Preferred Paths**.

Auxiliary Splay Trees: Every preferred path is stored inside its own self-adjusting **Splay Tree**, keyed by node depth (shallowest nodes on the left, deepest on the right).

`Access(v)` Operation: The core superpower of a Link-Cut Tree, which restructures the splay trees so that the path from the root down to node `v` becomes one single continuous preferred path with no preferred child below `v`.

`Link(u, v)` and `Cut(v)`: Connecting two separate trees by adding an edge, or severing the edge between a node and its parent-both in $\mathcal{O}(\log n)$ amortized time.


How Does a Link-Cut Tree Work Conceptually?

A standard tree becomes a nightmare to query if nodes can be arbitrarily disconnected and reattached millions of times-even worse if a single tree is stretched into a long, unbalanced chain. A Link-Cut Tree solves both problems by decomposing the *represented tree* into paths and storing each path inside a *balanced Splay Tree* connected by `path-parent` pointers.

Calling `Access(v)` walks up `path-parent` links and splays nodes to assemble the exact root-to-`v` route into one balanced splay tree. Once assembled, finding the path sum, path maximum, or Lowest Common Ancestor (LCA)-or cutting/linking an edge-takes a single step at the splay tree root.


Where Are Link-Cut Trees Used in the Real World?

Maximum Network Flow Algorithms (Dinic's / Goldberg-Tarjan): Push flow along augmenting paths of vertices in $\mathcal{O}(\log V)$ time instead of walking edge by edge.

Dynamic Minimum Spanning Trees: Maintain the cheapest spanning network as communication links are added, removed, or re-weighted in real time.

Dynamic Connectivity & LCA Queries: Answer whether two nodes are in the same connected component as edges break and heal dynamically.


Summary

A Link-Cut Tree combines path decomposition with self-adjusting Splay Trees, enabling logarithmic path queries and structural link/cut surgeries on dynamic forests.
