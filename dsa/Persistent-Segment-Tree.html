Persistent Segment Tree

A Persistent Segment Tree (also known as a **Chairman Tree**) is a special type of segment tree that preserves every historical version of itself after every update by reusing unchanged subtrees and only creating new nodes along the single modified root-to-leaf path.

Imagine editing a 1,000-page encyclopedia where you want to save a complete snapshot of the entire book every time you fix a single typo. Instead of photocopying all 1,000 pages for Version 2, you print *only* the 1 revised page and a new Table of Contents that points to the 999 original pages plus your 1 new page. A persistent segment tree saves complete historical snapshots using this exact path-copying trick.


Understanding the Basic Terminology

Path Copying: Creating only $\mathcal{O}(\log n)$ new nodes along the path from the root to the updated leaf, while wiring all untouched sibling pointers directly to the previous version's nodes.

Version Root Array: An array of root pointers where `roots[v]` gives you instant access to the state of the entire segment tree as it existed at version `v`.

Structural Sharing: The overlap where multiple version trees share the vast majority of their internal nodes safely in memory.


How Does a Persistent Segment Tree Work Conceptually?

When you update a single element in a standard segment tree, only the $\mathcal{O}(\log n)$ nodes along a single vertical path from the root to that leaf actually change their values; the other $99.9\%$ of the tree stays identical. Instead of overwriting those $\mathcal{O}(\log n)$ nodes in place, a persistent segment tree allocates new copies of just those nodes, links their unmodified side branches to the old tree, and returns a brand-new root node.

With $m$ updates on an array of size $n$, you get $m$ complete, queryable historical segment trees using only $\mathcal{O}(n + m \log n)$ total memory instead of $\mathcal{O}(n \cdot m)$.


Where Are Persistent Segment Trees Used in the Real World?

Time-Travel Database Queries: Answer range aggregation queries *"as of 3:15 PM yesterday"* without replaying transaction logs from scratch.

Range $K$-th Smallest Queries (2D Range Counting): Find the $k$-th smallest number in any subarray $[L, R]$ by subtracting the frequency segment tree at version $L-1$ from version $R$.

Version Control & Undo Systems: Maintain lightweight snapshots of hierarchical state across thousands of edits.


Summary

A persistent segment tree gives a segment tree a time machine, using path copying to preserve every past version of your data with just a handful of new nodes per update.
